# CloudPSS Skill 专业质量评价方法

## 一、目标

本文用于评价 CloudPSS skill 的电力系统仿真专业质量。

它补充 `contributor-guide.md` 和 `maintainer-guide.md` 中的结构、依赖、发布门禁要求，重点回答：

1. skill 解决的电力问题是否定义清楚
2. 采用的模型、公式、单位和算法是否合理
3. CloudPSS 仿真案例是否能证明该 skill 的专业有效性
4. 输出结果是否能被工程人员正确理解和复核
5. 该 skill 是否适合标记为 `experimental`、`validated` 或进入发布目录

本文不评价文案是否流畅、目录是否完整、Agent 触发描述是否友好。这些内容由仓库通用规范评价。

## 二、基本原则

### 2.1 先评价能力边界，再评价实现

一个专业质量合格的 skill 必须先说清楚它是什么。

应明确：

- 是仿真执行器、模型编辑器、波形后处理器、工程筛查器，还是报告生成器
- 是否会修改云端模型
- 是否会创建扰动、故障、检修或扫描工况
- 是否依赖已有仿真结果，还是会主动提交 CloudPSS job
- 输出是工程初筛结果、标准计算结果，还是正式校核结论

如果能力边界不清楚，即使代码能运行，也不能视为专业质量合格。

### 2.2 真实仿真通过不等于专业验证充分

`validate-skill`、`check_skill.py` 和 `release-check` 只证明结构、治理和基本一致性。

真实 CloudPSS job 通过可以证明 SDK 调用、模型加载、仿真提交、结果读取和产物导出链路有效。

但专业验证还需要继续判断：

- 模型是否覆盖该 skill 声称的物理现象
- 通道是否是该问题的直接观测量
- 结果是否和理论、标准算例、工程经验或其他工具一致
- 误差、近似和不确定性是否写清楚

### 2.3 近似可以接受，但必须显式标记

电力系统仿真 skill 可以采用工程近似，例如：

- 由功率和电压估算电流
- 由短路容量推导戴维南等值
- 用滑动 RMS 做暂降暂升初筛
- 用目标频点投影做谐波初筛
- 用 RoCoF 或转速偏差做暂态稳定筛查

这些近似不必然降低 skill 质量。质量问题在于是否隐藏近似、是否把初筛结果包装成正式校核结果。

## 三、专业质量评价维度

建议对每个电力仿真 skill 按以下十个维度评价。

### 3.1 问题定义和适用边界

检查项：

- skill 名称、description、When to use 和 Constraints 是否一致
- 是否说明适用的仿真类型，例如 powerflow、EMT、RMS、暂态稳定、波形后处理
- 是否说明不适用的场景
- 是否区分工程初筛、研究分析、标准校核和自动化执行
- 是否避免过度宣称

常见问题：

- 波形后处理 skill 宣称自己是标准短路计算器
- 只分析已有结果，却暗示会自动创建故障
- 只在单一公开模型上跑通，却宣称适用于所有电网场景

### 3.2 理论依据和公式合理性

检查项：

- 核心公式是否正确
- 物理量定义是否清楚
- 是否说明公式来源或工程口径
- 是否区分精确计算、标准方法和工程近似
- 公式中是否有隐藏假设

示例：

短路容量和戴维南等值类 skill 应至少说明：

```text
Ssc = sqrt(3) * Vll * I
Zth = Vll^2 / Ssc
Zth(pu) = Sbase / Ssc
SCR = Ssc / Srated
ESCR = (Ssc - Qcomp) / Srated
```

频率响应类 skill 应说明：

- 频率或转速通道的来源
- 标幺转速与 Hz 的转换
- RoCoF 的数值微分方法
- 稳态窗口和最大偏差的定义

谐波和电能质量类 skill 应说明：

- 基波频率
- 分析窗口
- THD 计算口径
- 是否使用 FFT、目标频点投影或其他方法
- 是否满足正式标准测量窗口要求

### 3.3 单位、标幺和基准体系

这是专业审查中最容易出错的部分。

检查项：

- 电压是线电压还是相电压
- 电流单位是 A、kA 还是 pu
- 功率单位是 W、kW、MW、MVA 还是 pu
- 阻抗是 ohm 还是 pu
- 标幺基准是否显式给出
- `Sbase`、`Vbase`、`Srated` 的含义是否区分
- 三相公式是否使用正确的 `sqrt(3)` 因子
- 公式中的输入单位和输出单位是否自洽

建议要求：

- 所有对外配置项名称携带单位，例如 `base_voltage_kv`、`system_base_mva`
- 输出字段名称携带单位或明确为 pu，例如 `short_circuit_mva`、`z_th_ohm`、`z_th_pu`
- Markdown 报告中不要只写数值，应写单位

### 3.4 仿真模型和案例有效性

检查项：

- 使用的 CloudPSS 模型是否真实可访问
- 模型是否包含该 skill 需要的物理现象
- 模型是否包含足够的观测通道
- 模型是否有明确的扰动、故障、检修、扫描或稳态工况
- 验证案例是否覆盖正常路径和关键退化路径
- 是否记录 job id、模型 RID、关键参数和验证日期

验证案例分级：

| 等级 | 含义 | 评价 |
| --- | --- | --- |
| L0 | 只通过结构校验 | 不能证明专业有效性 |
| L1 | 使用真实 CloudPSS 模型跑通 job | 证明链路有效 |
| L2 | 模型包含目标物理现象和直接观测通道 | 可以支持初步专业验证 |
| L3 | 有理论值、手算值、标准算例或其他工具对照 | 可以支持 `validated` 的专业可信度 |
| L4 | 覆盖多模型、多工况、边界条件和回归阈值 | 可作为发布级核心 skill |

### 3.5 观测通道和数据可观测性

检查项：

- 目标指标是否来自直接通道，还是由其他通道估算
- 如果使用估算，是否在结果中标记方法
- 通道命名是否可配置
- 自动通道选择是否有保守规则
- 缺少关键通道时是失败、降级还是给出近似
- 多通道时间轴是否一致

示例：

`short-circuit-analysis` 如果有真实电流通道，应优先使用真实电流。若公开模型只有功率和电压通道，可以使用 `estimated_from_power_voltage`，但输出和文档必须说明该结果是等效近似。

### 3.6 数值算法和窗口选择

检查项：

- 分析窗口、故障窗口、稳态窗口、参考窗口是否可配置
- 默认窗口是否适合默认验证模型
- RMS、FFT、差分、积分、插值、排序等算法是否稳定
- 是否处理采样率、窗口长度、样本数不足问题
- 是否检查时间轴单调性
- 是否避免除零和低电压异常
- 是否说明数值平滑、滤波或阈值选择

常见风险：

- 默认窗口包含启动暂态，却将结果解释为稳态指标
- 用瞬时电压波形直接当 RMS/pu 电压参与恢复判据
- 没有检查采样率就计算高次谐波
- RoCoF 用单点差分导致噪声放大

### 3.7 标准、工程参考和对标工具

skill 不一定要完整实现标准，但应说明参考边界。

可参考的公开标准和工具类型包括：

- IEC 60909、IEEE 551：短路电流和等效电压源法相关口径
- IEEE 2800、NERC 弱短路强度相关资料：IBR 并网、SCR/ESCR 和弱网风险解释
- IEC 61000 系列：电能质量、谐波、暂降暂升、闪变等测量口径
- IEEE 1547：分布式电源并网性能与测试背景
- pandapower、GridCal、OpenDSS、PSCAD、MATPOWER：可作为交叉验证工具或方法参考

注意：

- 文档中可以写“参考”，但不能暗示 skill 已完整符合某标准，除非有专门的标准符合性验证
- 如果只做初筛，应明确写“不替代 IEC/IEEE/NERC 标准级研究或设备校核”

### 3.8 结果解释和工程可用性

检查项：

- 输出是否包含关键摘要字段
- 是否给出排序、等级、越限项或最严重通道
- 是否能解释为什么 PASS、WARNING 或 VIOLATION
- 报告是否说明近似、阈值和下一步工程建议
- 指标名称是否能被电力工程师理解
- JSON、CSV、Markdown 是否字段一致

好的输出应让 reviewer 能回答：

- 哪个通道最严重
- 哪个指标越限
- 使用了什么数据来源
- 阈值是多少
- 结果是否来自直接仿真量还是估算量
- 下一步应该复核什么

### 3.9 鲁棒性和失败模式

检查项：

- CloudPSS job 失败或超时时是否失败退出
- 目标通道不存在时是否给出清晰错误
- 样本不足、时间轴不一致、窗口为空时是否失败
- 无法计算某个指标时是否标记 `not_assessed`，而不是输出假 0
- 配置非法时是否提前拒绝
- 是否避免把异常吞掉后继续导出报告

建议：

- 对物理上不成立的输入直接 raise error
- 对可选但缺失的输入输出 `not_assessed`
- 对近似路径输出 method 字段

### 3.10 可复现性和审计证据

检查项：

- `SKILL.md` 是否记录验证模型、job id、关键通道和关键结果
- `evals/evals.json` 是否覆盖核心专业指标
- 验证脚本是否能复现同一类结果
- 产物是否输出到 `results/skill-verification/...`
- 是否避免提交 `skills/**/artifacts`、`__pycache__`、`.env`、token
- 是否记录默认阈值和验证配置

## 四、评分建议

维护者可以采用 0 到 3 分评价每个专业维度。

| 分数 | 含义 |
| --- | --- |
| 0 | 未说明、错误或不可审查 |
| 1 | 有基本实现，但假设、单位、模型或边界不充分 |
| 2 | 工程上合理，有真实验证和清楚约束 |
| 3 | 有多案例或对标验证，适合长期回归和发布 |

建议总评：

| 总分 | 建议结论 |
| --- | --- |
| 0-11 | 不通过，需要重做专业定义或核心算法 |
| 12-19 | 可作为 `draft` 或内部实验，不建议共享 |
| 20-25 | 可作为 `experimental`，但需补验证或边界说明 |
| 26-30 | 可作为 `validated`，真实验证和专业边界基本充分 |

如果存在以下任一问题，即使总分较高，也应阻塞通过：

- 核心公式错误
- 单位或标幺基准错误导致结果量级不可信
- 使用假模型、占位模型或无法复现的验证证据
- 声称标准级结论但只做了工程初筛
- 隐藏关键近似路径
- 缺少 CloudPSS 真实验证却标记 `maturity: validated`

## 五、成熟度判定

### 5.1 `draft`

适用情况：

- 只有文档或原型代码
- 未完成真实 CloudPSS 验证
- 算法或模型边界尚不清楚

### 5.2 `experimental`

适用情况：

- 结构校验通过
- 至少有最小验证脚本
- 公式和单位没有明显错误
- 但模型覆盖不足、通道不充分或缺少对标

示例：

- 故障场景蓝图编辑器只做模型巡检和配置生成，不运行 EMT
- 扫描类 skill 结构通过，但尚未完成多工况真实验证

### 5.3 `validated`

适用情况：

- 已通过真实 CloudPSS 验证
- `SKILL.md` 记录模型、job id、关键配置和关键结果
- 验证模型包含目标物理现象或等价可解释路径
- 公式、单位、通道、窗口和近似边界清楚
- 输出报告、JSON、CSV 与 `evals` 一致

注意：

如果验证只证明链路跑通，而不能充分证明专业精度，仍可标记 `validated`，但必须在 Constraints 或 Live verification 中说明验证边界。

### 5.4 `published`

适用情况：

- 满足 `validated`
- 具备多模型或多工况回归
- 有误差阈值或对标依据
- 失败模式和边界条件覆盖充分
- 维护者确认适合团队共享 catalog

## 六、按 skill 类型的专业评价重点

### 6.1 潮流和稳态分析类

重点检查：

- 潮流算法类型和收敛状态
- 平衡节点、PV/PQ 节点、无功限值处理
- 电压越限、支路负载率、损耗和无功裕度
- N-1 或检修方式是否真实改变模型拓扑
- 结果是否区分不收敛、越限和正常

### 6.2 EMT 仿真和故障分析类

重点检查：

- 模型是否 EMT-ready
- 故障时间、切除时间、故障阻抗和测量通道是否明确
- 时间步长、采样率和窗口是否足够
- 电流、电压、功率通道是否直接可观测
- 暂态、故障中和故障后窗口是否区分

### 6.3 短路容量、戴维南和弱网类

重点检查：

- `Vll`、`I`、`Ssc`、`Zth`、`Sbase`、`Srated` 单位是否正确
- 真实电流通道和等效电流通道是否区分
- SCR/ESCR 阈值是否可配置
- 是否说明弱网判定只是初筛
- 是否说明 IBR 控制相互作用、阻抗扫描、动态稳定仍需单独研究

### 6.4 谐波和电能质量类

重点检查：

- 基波频率和分析窗口
- 采样率是否支持最高谐波
- THD、单次谐波、暂降、暂升、不平衡、直流偏置定义
- 是否区分瞬时波形、RMS 和 pu 值
- 是否说明不替代正式 IEC 61000 合规测量

### 6.5 频率响应和暂态稳定类

重点检查：

- 频率、转速、功角或电压通道来源
- 稳定判据是否和通道类型匹配
- RoCoF、最大偏差、恢复时间的计算方法
- 是否避免把瞬时电压当成恢复电压
- 是否说明筛查结论不等于完整暂态稳定结论

### 6.6 参数扫描和灵敏度类

重点检查：

- 参数修改是否只作用于本地工作副本
- 扫描点数量、基准点和扰动幅度是否合理
- 失败点是否记录
- 灵敏度归一化口径是否说明
- 是否避免保存或污染云端模型

## 七、审查输出模板

维护者审查时建议使用以下格式。

```text
结论：通过 / 有条件通过 / 不通过

专业质量判断：
- 问题定义：
- 公式和单位：
- 仿真模型和通道：
- 验证证据：
- 工程边界：

阻塞问题：
- ...

非阻塞建议：
- ...

建议 maturity：
- draft / experimental / validated / published
```

如果没有阻塞问题，应明确说明“专业质量通过”，但仍可列出后续增强建议。

## 八、示例：short-circuit-analysis

以 `short-circuit-analysis` 为例，可以这样评价。

专业定位：

- 它是基于 CloudPSS EMT 结果的短路电流、短路容量、戴维南等值和 SCR/ESCR 初筛 skill。
- 它不创建故障，不修改云端模型。
- 它不替代 IEC 60909 设备校核级短路计算，也不替代 IEEE 2800/NERC 接入研究。

公式评价：

- `Ssc = sqrt(3) * Vll(kV) * I(kA)` 与三相短路容量量纲一致。
- `Zth = Vll^2 / Ssc` 在 `kV` 和 `MVA` 下得到 `ohm`，量纲一致。
- `Zth(pu) = Sbase / Ssc` 在相同 MVA 基准下成立。
- `SCR = Ssc / Srated` 和 `ESCR = (Ssc - Qcomp) / Srated` 适合作为弱网初筛。

模型和通道评价：

- 已在 `model/CloudPSS/IEEE3` 上完成真实 CloudPSS EMT 验证。
- 公开 IEEE3 验证路径缺少直接电流通道，因此使用功率/电压估算等效电流。
- 该验证可以证明链路有效，但专业精度还应补充含真实电流通道或已知短路容量的模型案例。

结论示例：

```text
作为 EMT 波形驱动的短路容量、戴维南等值和 SCR/ESCR 初筛 skill，专业质量合格。
公式链路和单位口径合理，真实 CloudPSS 验证有效，工程边界说明清楚。
主要后续增强项是补充直接电流通道模型、标准算例或第三方工具对标，以提高专业精度证据等级。
```

## 九、维护建议

每新增或升级一个电力仿真 skill，维护者应至少保留以下证据：

- `SKILL.md` 中的 Live verification
- `evals/evals.json` 中的专业验收标准
- 验证脚本
- 模型 RID、job id、关键通道、关键参数
- 关键结果摘要
- 近似路径说明
- 下一步专业增强建议

当 skill 的算法、默认模型、默认窗口、单位基准或输出字段发生变化时，应同步更新专业质量评价结论。
